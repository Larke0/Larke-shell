# Hyprland dotfiles

Modular, per-host Hyprland config. The tracked tree is host-agnostic;
anything that varies between machines lives in `custom/hyprland.conf`,
which is gitignored.

## Bootstrap on a new machine

```sh
git clone <repo> ~/.config/hypr
cp ~/.config/hypr/custom/hyprland.conf.example ~/.config/hypr/custom/hyprland.conf
$EDITOR ~/.config/hypr/custom/hyprland.conf   # set monitors, GPU, autostarts
chmod +x ~/.config/hypr/scripts/*.sh ~/.config/hypr/GameWorkspace/scripts/*.sh
```

Reference `custom/examples/Desktop.conf` and `custom/examples/Laptop.conf`
for full working setups.

## Layout

```
hypr/
├── hyprland.conf              # entry point — sources custom first, then modules
├── hypridle.conf              # idle daemon
├── hyprlock.conf              # lock screen
├── xdph.conf                  # xdg-desktop-portal
│
├── custom/                    # per-host overrides
│   ├── hyprland.conf          # ← LOCAL, gitignored. Active per-host config.
│   ├── hyprland.conf.example  # template, copy on a new machine
│   └── examples/              # full reference configs
│       ├── Desktop.conf
│       └── Laptop.conf
│
├── hyprland/                  # tracked module configs (host-agnostic)
│   ├── env.conf               # env vars (no GPU-specific drivers)
│   ├── monitor.conf           # workspace pinning via $monitor1/$monitor2
│   ├── permissions.conf
│   ├── general.conf           # input, programs, misc
│   ├── rules.conf             # window rules
│   ├── looks.conf             # decoration, animations
│   ├── keybinds.conf
│   ├── execs.conf             # system-essential autostarts only
│   ├── specialWorkspaces.conf
│   ├── theme.conf             # autogenerated by theming tool
│   └── hyprlock.conf          # alternate lock variant
│
├── GameWorkspace/             # game-mode special workspace
├── scripts/                   # workspace + utility scripts
└── scheme/                    # autogenerated color scheme (current.conf gitignored)
```

## How `custom/hyprland.conf` plugs in

The root `hyprland.conf` sources `custom/hyprland.conf` **before** the
tracked modules. That means:

- Variables defined in `custom/` (e.g. `$monitor1 = DP-3`) are available
  to every tracked config that follows.
- `monitor =`, `exec-once =`, `device { ... }`, `env =` lines in `custom/`
  are additive — they stack with what tracked configs declare.
- For value overrides (e.g. `general { gaps_in = 10 }` to override the
  tracked default), edit the tracked file directly or add a second
  `source = ~/.config/hypr/custom/overrides.conf` line at the bottom of
  the root `hyprland.conf`.

## What lives where

| Concern                    | Location                         |
| -------------------------- | -------------------------------- |
| Monitor outputs            | `custom/hyprland.conf`           |
| GPU / VA-API driver        | `custom/hyprland.conf`           |
| Touchpad / per-device      | `custom/hyprland.conf`           |
| Autostart per-machine apps | `custom/hyprland.conf`           |
| Workspace ↔ monitor pins   | `hyprland/monitor.conf` (uses `$monitor1`/`$monitor2`) |
| Keybinds                   | `hyprland/keybinds.conf`         |
| Window rules               | `hyprland/rules.conf`            |
| Look & feel                | `hyprland/looks.conf`            |
| System autostarts          | `hyprland/execs.conf`            |

## NixOS / home-manager notes

- All paths are `$HOME`-relative; nothing references `/usr/local` or
  Arch-only locations except a couple of `permission =` entries in
  `hyprland/permissions.conf`. Adjust those for your distro's paths.
- When home-manager symlinks the tree into `~/.config/hypr`, the
  `~/.config/hypr/scripts/...` references in keybinds resolve through
  the symlink — no rewriting needed.
- `custom/hyprland.conf` should be unmanaged by home-manager so the
  user can edit it freely on each host.
